# Library Management API

FastAPI + SQLAlchemy 2 + psycopg 3 on Neon Postgres. Maps the existing `neondb` schema (16 tables) - no tables are created by the app.

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

`.env` needs:

```
DATABASE_URL=postgresql://...neon.tech/neondb?sslmode=require&channel_binding=require
JWT_SECRET=<at least 32 random characters>
# optional
ACCESS_TOKEN_EXPIRE_MINUTES=60
CORS_ORIGINS=["http://localhost:3000"]
DEBUG=false
```

### One-time database steps

1. **Fix the unique constraints** (otherwise a copy can only be returned once, ever):
   ```bash
   psql "$DATABASE_URL" -f migrations/001_fix_unique_constraints.sql
   ```
2. **Set a real password** for a staff user (the seeded hashes are truncated and cannot be logged in with):
   ```bash
   .venv/bin/python -m scripts.set_password rajesh.sharma@library.edu.in
   ```

## Run

```bash
.venv/bin/python main.py                       # dev, auto-reload, http://127.0.0.1:8000
.venv/bin/uvicorn main:app --host 0.0.0.0 --workers 4   # production
```

Interactive docs: <http://127.0.0.1:8000/docs> - log in at `POST /api/v1/auth/login`, copy `access_token`, click **Authorize** and paste it.

## Deploy on Render

`render.yaml` defines the service. Push the repo to GitHub, then in Render choose **New → Blueprint** and pick the repo.

- **Set `DATABASE_URL`** in the Render dashboard (it is not in git - `.env` is ignored). `JWT_SECRET` is generated by Render.
- Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips="*"`
- Health check: `/health`. Python version pinned in `.python-version` / `PYTHON_VERSION`.
- Due dates and fines use `TIMEZONE` (default `Asia/Kolkata`), not the server's UTC clock.
- The free plan sleeps after ~15 min idle; the first request after that takes ~30-60 s.

## Layout

```
app/
  core/        config, database engine, JWT/bcrypt, auth dependencies, errors
  models.py    ORM mappings of the existing tables
  schemas/     request / response models (Pydantic v2)
  services/    business rules: circulation.py, library_settings.py, activity log, pagination
  routers/     HTTP endpoints, all under /api/v1
migrations/    SQL to run once against the database
scripts/       admin utilities
```

## Endpoints (all under `/api/v1`)

| Area | Endpoints |
|---|---|
| Auth | `POST /auth/login`, `GET /auth/me`, `POST /auth/change-password` |
| Catalogue | `/books` (search `q`, filters, `available_only`, sort), `/books/{id}` with copies, `/copies`, `/copies/{id}/history`, `/authors`, `/categories`, `/publishers` |
| Members | `/members` (search), `/members/{id}/summary` (can they borrow?), `/loans`, `/fines`, `/reservations`; `DELETE` deactivates |
| Circulation | `POST /loans/issue`, `/loans/{id}/return`, `/loans/{id}/renew`, `/loans/{id}/lost`, `POST /loans/maintenance/mark-overdue` |
| Fines | `/fines` (filters), `POST /fines/{id}/pay` (partial payments) |
| Reservations | `/reservations`, `POST /reservations/{id}/cancel`, `POST /reservations/maintenance/expire` |
| Reports | `/reports/dashboard`, `/overdue`, `/popular-books`, `/top-borrowers`, `/categories`, `/activity-logs` (admin) |
| Admin | `/users` (+ `reset-password`), `/settings/{key}`, `/departments`, `/courses` |
| System | `GET /health` |

## Business rules

- **Issue** is refused when: the copy is on loan or lost; the member is inactive or their membership has expired; they have reached their limit (`max_books_student` / `max_books_faculty` / `max_books_staff`); they have an overdue book or unpaid fines; or every available copy is held for other members' pending reservations. A member's own pending reservation is marked *Fulfilled* on issue.
- **Due date** = today + `loan_period_days`, unless the request gives one.
- **Return** creates a fine of `days late x fine_per_day_inr`. Returning with `condition: "Lost"` marks the loan *Lost*.
- **Renew** extends by `loan_period_days`. It is refused for overdue loans or when another member has reserved the book.
- **Lost** adds the replacement charge plus any overdue fine and takes the copy out of circulation.
- Rows are locked with `SELECT ... FOR UPDATE` during issue, return and payment, so concurrent requests cannot double-issue a copy.
- Every change is written to `activity_logs` with the staff user and IP address, in the same transaction.
- **Roles:** *Librarian* handles circulation, members and catalogue edits. *Admin* also manages users and settings, deletes records, and reads the audit log.

Money is returned as 2-decimal strings (`"50.00"`).

Schedule the two `maintenance` endpoints daily (cron) to keep loan and reservation statuses current.
